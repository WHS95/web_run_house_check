# `lib/domain/`

비즈니스 룰을 격리하는 도메인 레이어. **Supabase, Next, React 의존성 절대 금지**. 단위 테스트 가능한 순수 함수만 둔다.

자세한 설계는 [`docs/plans/2026-04-28-bff-refactor-design.md`](../../docs/plans/2026-04-28-bff-refactor-design.md) 참조.

## 디렉토리 구조

```
lib/domain/<name>/
├── policies.ts       # 권한·정책 (한글 함수)
├── workflow.ts       # 상태 전이 (한글 함수)
├── validators.ts     # Zod schema · 입력 검증
├── messages.ts       # 사용자 메시지 조립
├── types.ts          # 도메인 타입 (영어)
└── *.test.ts         # Vitest 단위 테스트 (1:1 필수)
```

## 룰

1. **외부 의존 import 금지** — `@/lib/supabase/*`, `next/*`, `react`, `@/app/**`, `@/components/**` 모두 ESLint로 차단.
2. **모든 `.ts` 파일은 같은 폴더의 `*.test.ts`를 가진다** (`types.ts`, `index.ts` 제외). `npm run check:bff`가 검증.
3. **함수명은 한글**. 패턴은 아래 §컨벤션 참조.
4. **타입·변수·필드명은 영어** (Supabase row와 결합).

## 한글 메소드명 컨벤션

| 동작 | 패턴 | 예시 |
|------|------|------|
| `boolean` 판정 | `~인가`/`~가능한가`/`~여부` | `유효한가`, `미등록허용`, `매니저_여부` |
| 실행 | `~하기` | `출석등록하기` |
| 변환·조립 | `~생성`/`~조립` | `알림메시지_조립` |
| 검증(throw) | `~검증` | `권한_검증` |
| Type guard | `~인` | `출석된_사용자인` |
| 상태 전이 | `~로_전환`/`~로_변경` | `대기로_전환` |

- 2단어 이하: 붙여 쓰기 (`출석등록하기`)
- 3단어+ 또는 의미 단위 분리: `_` (`출석시간_유효한가`)
- 영어 약어: `_` + 영어 (`PostHog_이벤트전송`)

### 금지 패턴

- ❌ 한·영 혼합 단어: `get출석`, `submit출석`
- ❌ 한자: `出席`
- ❌ 모호한 일반명사 단독: `처리`, `실행`, `로직`
- ❌ 띄어쓰기: `출석 등록 하기`
- ❌ 축약: `출등록`
